# Webserver 串行上传下载接口设计方案

## 1. 目标与约束

- 支持浏览器、CLI、curl、wget 上传下载。
- 同一文件分块串行上传，不同文件支持有界并发。
- 支持断点续传、大小校验和可选客户端 Hash 校验。
- 使用文件系统和 JSON 持久化，不引入数据库、Redis 或任务队列。
- 上传地址必须包含完整目标文件名；不支持目录级上传地址 `/upload/目录/`。
- 本文为 okserver 的接口契约；当前实现及验收命令见 README。macOS 留待 CI 验收。

## 2. 接口设计

| 地址 | 方法 | 功能 |
|---|---|---|
| `/upload/目录/文件名` | POST | 单次上传，支持原始文件流和 multipart/form-data |
| `/upload/目录/文件名` | PUT | 完整文件上传、串行分片及断点续传 |
| `/upload/目录/文件名` | HEAD | 查询任务状态、已确认偏移和总大小 |
| `/upload/目录/文件名` | GET | 仅配合 Content-Type: application/offset 查询偏移 |
| `/upload/目录/文件名` | DELETE | 取消未完成任务，清理暂存数据 |
| `/download/目录/文件名` | GET、HEAD | 下载和文件信息查询，支持 HTTP Range |

目录和文件名均相对于配置的文件根目录。URL 路径由客户端逐段编码，服务端统一解码、规范化并验证。目录级地址、路径穿越、内部状态目录及非法文件名均拒绝。

POST 表单只接受一个名为 `file` 的文件部分。最终保存位置完全由 URL 决定，不使用表单文件名拼接路径；缺少文件、多个文件和不合法表单均返回 400。

只有 multipart/form-data 按表单解析；普通原始上传接受 curl/wget 默认 Content-Type、application/octet-stream 以及缺省类型。Content-Type 不承担身份认证职责。

网页保留 `/`、`/workspace/*` 及静态资源路由；管理 API、SSE 和健康检查继续使用专属路由。上传和下载不经过 SPA 回退。

## 3. 调用示例

以下命令以 Bash 换行表示；Windows PowerShell 使用 curl.exe 避免命令别名。

```bash
# curl 单次原始上传
curl --fail-with-body --data-binary "@file.zip" \
  "https://服务器/upload/目录/file.zip"

# curl 表单上传：URL 仍需完整文件名
curl --fail-with-body -F "file=@file.zip" \
  "https://服务器/upload/目录/file.zip"

# wget 单次上传
wget -O - --post-file="file.zip" \
  "https://服务器/upload/目录/file.zip"

# 可选完整文件 SHA-256 校验
curl --fail-with-body --data-binary "@file.zip" \
  "https://服务器/upload/目录/file.zip?sha256=<十六进制SHA256>"

# 查询续传偏移，响应包含 Offset-Length 和参考续传命令
curl -H "Content-Type: application/offset" \
  "https://服务器/upload/目录/file.zip"

# 使用查询得到的明确偏移续传
curl --fail-with-body -C 8388608 -T "file.zip" \
  "https://服务器/upload/目录/file.zip"

# 断点下载
curl --fail-with-body -C - -o "file.zip" \
  "https://服务器/download/目录/file.zip"
wget -c -O "file.zip" "https://服务器/download/目录/file.zip"
```

认证和 TLS 参数沿用 `curl -u`、`--cacert` 及 wget 对应参数。curl HTTP 上传不承诺 `-C - -T` 自动协商远端偏移；可靠流程是查询后显式指定 `-C 数值`。wget 上传仅承诺单次 POST，自动上传续传由浏览器和 CLI 提供。

## 4. 任务与串行分片协议

首次 POST 或 PUT 自动创建内部任务，无独立创建接口。服务端生成任务 ID；客户端以目标路径访问，任务 ID 用于日志、事件和内部存储。同一目标路径只允许一个活动任务，多个客户端不得同时写入。

浏览器和 CLI 默认以 8 MiB 分片，可由配置调整。每次只发送一个分片：

```http
PUT /upload/目录/file.zip
Content-Range: bytes 0-8388607/1073741824
Content-Length: 8388608
X-Chunk-SHA256: <可选的分片SHA256>
```

总大小必须已知，范围必须合法，起始位置必须等于服务端已确认偏移。每个分片完整接收、校验和持久化后才更新偏移并确认成功。失败分片回滚至上次确认位置。

PUT 无 Content-Range 时表示从零上传完整文件；已有活动任务时返回冲突，不隐式覆盖。POST 是单次上传，不自动追加；已有任务时返回冲突，客户端可显式取消后重试。

最终字节到齐后自动进入校验，无单独 complete 接口。空文件通过 Content-Length: 0 的 POST 完成。

HEAD 状态示例：

```http
HTTP/1.1 200 OK
Upload-Offset: 8388608
Upload-Length: 1073741824
Upload-State: uploading
Offset-Length: 8388608
Cache-Control: no-store
```

状态包括 uploading、verifying、completed、failed、canceled。无任务返回 404；Upload-Length 仅在总大小已知时提供。HEAD 的 Content-Length 不表示远端文件总大小，客户端读取专用字段。

首次 PUT 中断后可以继续查询已确认偏移。原始 POST 中断时，已按内部固定块持久化的数据可供 PUT 续传；未确认尾部丢弃。表单 POST 中断后重传整个文件，不承诺表单续传。

## 5. 幂等、重试和结果

- 分片偏移不匹配返回 409，并返回服务端当前偏移；不直接重复追加。
- 请求成功但响应丢失时，客户端先查询状态；偏移已推进则跳过对应数据，否则重传。
- 网络错误、408、429 和可重试的 5xx 使用指数退避与随机抖动，遵守 Retry-After；认证和参数错误直接提示。
- 完成后的重复状态查询返回 completed；完成后重复上传默认冲突，避免意外覆盖。
- 已存在目标文件默认返回 409；首期不提供隐式覆盖。
- 单个分片成功返回 204；同步发布成功返回 201；进入后台最终校验返回 202。
- 最终校验是持久化状态任务，由进程内有界 Worker 执行；重启后恢复。客户端通过 HEAD 或 SSE 等待 completed，不能把 202 当作最终成功。

错误使用明确状态码及统一错误内容：400 参数错误，401/403 认证或权限错误，404 无任务或文件，409 状态冲突，412 覆盖版本不匹配，413 超限，422 Hash 不匹配，423 任务忙，429 并发限流，507 空间不足。不要将预期的断流直接包装成无说明的 500。

## 6. 大小与 Hash 校验

原始已知长度上传核对 Content-Length 和实际接收字节；分片核对 Content-Range、当前块长度及文件总大小。multipart 请求总长度包含边界，必须单独统计文件部分大小。

未知长度原始 POST 在最大文件大小和磁盘配额约束下流式接收。可选 `size=<字节数>` 声明预期完整文件大小；声明与实际长度不符时不发布。分片上传不接受未知总长度。

所有文件、分片和续传前缀摘要统一使用 SHA-256，不支持其他摘要算法。完整文件 Hash 可通过查询参数 `sha256` 提供，值为 64 位十六进制字符串；服务端接受大小写并统一保存为小写。

查询参数可能进入访问日志，日志应过滤 Hash 查询字段。另支持 `X-File-SHA256` 请求头，取值优先级为：查询参数 `sha256` > 请求头 `X-File-SHA256`。只要参数存在，就使用参数值并忽略请求头，无需两者一致；参数为空、重复或格式错误时返回 400，不回退到请求头。参数不存在时才读取请求头，请求头为空、重复或格式错误时返回 400。两者均不存在时允许不提供客户端摘要。

完整文件预期 Hash 在首次提供时绑定任务；后续可以省略，重新提供时必须一致。浏览器和 CLI 在最后一片提供完整摘要，避免上传前全盘扫描。分片可带 X-Chunk-SHA256，失败时回滚该块并允许重试。完整文件 Hash 不由分片 Hash 拼接生成。

服务端最终流式计算 SHA-256 并写入 JSON manifest，只持久化这一种摘要。客户端未提供 Hash 时允许上传，但最终结果仅代表服务端收到的内容，不能证明与客户端原文件一致。客户端提供值时必须在发布前完成比较。

完整 Hash 校验失败后任务进入 failed，不发布文件；该路径下一次从零上传创建新任务，失败记录在保留期内仍可按 ID 查询。不提供秒传，避免上传前强制扫描完整大文件和引入内容归属验证。

最终 SHA-256 直接通过下载接口的响应头返回，客户端无需额外调用 Hash 查询接口。迁移时移除其他算法依赖、配置、协议字段及多算法查询入口。

用户也可使用系统工具核对同一个 SHA-256 值：Windows PowerShell 使用 `Get-FileHash "C:\example.zip" -Algorithm SHA256`，Linux 使用 `sha256sum example.zip`。

## 7. 浏览器与 CLI

浏览器通过 Blob.slice() 按块读取，应用缓冲受分片大小及全局并发数约束。同一文件串行上传，不同文件有界并发。刷新后重新选择文件，核对本地文件信息并查询服务端偏移；localStorage 保存会话凭证及下载恢复摘要，服务端状态为准。浏览器进程总内存还包含引擎、文件缓存及 OPFS，不等于应用分片缓冲大小。

仅凭文件名、大小和修改时间不能可靠确认是原文件。自动续传前验证本地已上传前缀与服务端暂存内容的 SHA-256；HEAD 可按需返回确认前缀摘要。验证失败时拒绝追加，提示重新开始。该过程需要读取已上传前缀，但不要求整文件预扫描。

如用户选择完整文件校验，浏览器在 Worker 内增量计算，明确展示计算进度及读取成本。上传进度以服务端确认字节数为准，最终校验单独展示阶段。SSE 用于状态通知，断线后用 HEAD 补查。

CLI 保留认证、CA、超时及原有 -d、-c 参数，上传 URL 改为 /upload/...，下载 URL 为 /download/...。续传模式自动查询偏移、验证文件身份并串行发送；CLI 可使用本地文件指纹和摘要缓存减少重复计算。

curl 手动续传如不提供完整 Hash，用户需保证使用同一个源文件；大小和偏移不能识别内容替换。

## 8. 下载行为

下载支持 GET、HEAD、Range、If-Range、ETag、Last-Modified 和 Content-Disposition。只暴露已完成文件，暂存数据不可下载。客户端下载续传时验证远端文件身份，远端变化则重新下载或明确报错，禁止盲目追加。

GET、HEAD 和 206 响应均返回 `X-File-SHA256`，表示完整文件的 64 位十六进制 SHA-256；通过 `X-File-Size` 返回完整文件大小。206 的 Content-Length 只表示当前分片长度，不代表完整文件大小。完整文件摘要不得误用为当前 Range 的摘要。

响应头摘要必须对应本次实际下载的文件版本；文件被外部修改后必须使缓存失效并重新计算。文件大小和修改时间只能辅助检查，不能单独保证内容未变化；下载期间应固定可读取的文件版本，无法保证版本稳定时中止并重试。跨域场景通过 Access-Control-Expose-Headers 暴露 X-File-SHA256、X-File-Size、ETag、Content-Range 等客户端所需字段。

CLI 和浏览器 JS 管理的下载在完成后增量计算完整文件 SHA-256，与服务端响应头比较，匹配后才标记成功；CLI 校验通过后才将临时文件发布为正式文件。浏览器在 Worker 中增量计算，超大文件需使用具备磁盘读写能力的浏览器文件 API，避免整文件进入内存。浏览器原生链接下载无法由网页自动读取并校验下载结果，界面不得声称已经校验。

CLI 和支持文件读写 API 的浏览器实现同一文件并发下载，默认 4 路；CLI 通过 -parallel 配置 1～16 路，浏览器固定 4 路，并受服务端全局连接数限制。先通过 HEAD 获取大小、强 ETag 和 SHA-256，再按字节范围调度 GET；所有 Range 响应必须属于同一 ETag 和完整文件 SHA-256，并严格检查 206、Content-Range 和实际长度。服务器返回 200 时禁止当作分片写入，应停止并提示重新下载。文件版本变化时取消全部请求，重新操作时重新协商版本。

CLI 按偏移写入临时文件，持久化已确认下载区间和文件版本；失败只重试对应区间，重启后恢复缺失区间。浏览器采用支持按位置落盘的文件 API，并在单一写入协调器中串行提交已下载数据，避免写入竞争；无法可靠落盘时退回普通下载，不在内存中拼接超大文件。并发下载完成后顺序读取本地文件计算 SHA-256，通过后发布并标记成功。并发数不保证线性提速，需实测网络、磁盘、CPU 和内存。

大文件流式发送，限制并发和资源占用；超时策略允许持续传输，区分连接空闲与整个请求时长。

## 9. 持久化与安全发布

```text
server.files_dir/
  对外文件和子目录

server.states_dir/
  uploads/<任务ID>/
    metadata.json
  locks/
  budget/
  file-hashes.json

server.cache_dir/
  uploads/<任务ID>/
    payload.part
  streams/
    <流式暂存文件>
```

元数据保存版本、任务 ID、目标路径、总大小、确认偏移、预期 Hash、状态和更新时间。元数据原子更新；文件与目录同步策略复用现有持久化实现。

`server.files_dir`、`server.states_dir` 和 `server.cache_dir` 分别保存对外文件、会话状态和上传暂存数据，默认值为 `./files`、`./okserver_states` 和 `./okserver_cache`。三个目录互不重叠；旧 `server.path` 与 `upload.chunk_dir` 配置不再支持。保留已有成品时，将 `server.files_dir` 指向原 `uploads` 目录；旧会话状态不迁移，未完成上传不能续传。

启动恢复时核对缓存数据长度与确认偏移，截断未确认尾部；数据短于已确认偏移时报告损坏，禁止谎报进度。发布采用同文件系统原子操作；默认拒绝同名文件，调用方须显式请求覆盖并提供当前目标的 `If-Match` ETag。ETag 不匹配时拒绝发布；恢复流程处理发布成功但状态更新中断的情况。

任务锁、文件路径锁和全局资源预算统一实现。认证覆盖上传、状态、取消、下载和 Hash 查询；目标路径需防范路径穿越、符号链接越界及 Windows 特殊路径。取消只删除暂存数据，不删除已发布文件。过期任务定期清理，Hash manifest 更新需避免并发丢失。

## 10. 代码职责与迁移

| 模块 | 职责 |
|---|---|
| internal/server | HTTP 接入、路由、认证、参数与响应映射 |
| internal/upload | 任务、偏移、串行写入、校验和完成流程 |
| internal/uploadstore | JSON 元数据读写和恢复 |
| internal/storage | 暂存文件、锁、空间检查及原子发布 |
| internal/digest、hashmanifest | 增量摘要、文件摘要和最终记录 |

| 前端上传模块 | 分片调度、恢复、状态和进度展示 |

先调整上传核心和持久化状态，再实现统一 HTTP 入口，迁移 CLI、浏览器、启动提示和示例。所有调用迁移后删除原独立 curl、Tus 以及创建/完成上传入口，不保留多套上传协议。管理 API 和 SSE 继续承担查询、维护和通知职责。

## 12. 可靠性优化与实施阶段

以下方案均纳入当前实现，包括可靠串行上传、并发下载及显式覆盖；验收区分本地已执行与尚待 CI 的平台。

### 12.1 续传文件身份与会话隔离（首期）

自动续传时对服务端已确认前缀计算 SHA-256，客户端读取相同长度前缀进行比较；每次恢复验证一次，不逐分片重复扫描。超大前缀校验显示独立进度并支持取消。校验必须绑定任务 ID 和偏移，校验期间冻结写入或验证偏移未变化，防止比较过期状态。

任务绑定认证主体和目标路径。浏览器及 CLI 获取不可猜测的会话凭证，通过请求头携带；即使认证账号相同，不同客户端也不能交替修改任务。写入锁保证同一时刻仅一个写入者。会话凭证仅保存摘要，不进入 URL 和日志；恢复时重新认证并执行明确的会话接管流程，已有写入者未退出时返回冲突。

curl/wget 简单 POST 无需会话凭证。curl 手动 PUT 续传保持简便，通过认证、目标路径任务锁和偏移检查保护；未提供完整摘要时无法自动保证本地源文件身份，应明确这一边界。身份绑定不能单独解决同账号多客户端竞争，因此必须同时执行服务端写入互斥。

### 12.2 分片校验与增量 SHA-256（首期）

浏览器和 CLI 默认发送 X-Chunk-SHA256；curl/wget 保持可选。分片摘要不匹配返回 422，并保持原确认偏移；自动客户端在有界次数内重传缓存的当前块，反复失败后停止。

服务端串行写入时维护完整文件的增量 SHA-256，正常完成后直接输出最终摘要，避免再次全盘读取。只将已成功持久化的分片纳入确认状态；分片失败、取消或磁盘错误时恢复分片开始前的计算状态。计算状态使用受控内存快照，不将语言运行时内部状态作为长期 JSON 契约。

进程重启后顺序读取已确认前缀恢复摘要状态，再继续上传；最后字节已收到但尚未完成发布的任务同样恢复校验。散列状态必须与任务、确认偏移、暂存文件版本一致。无法证明状态一致时重新读取暂存数据，禁止使用过期摘要发布文件。

### 12.3 下载版本一致性（首期）

受程序管理的文件发布后保持不可变，替换产生新版本。下载在锁定的版本上打开文件并获取对应元数据，Range、ETag 和 SHA-256 均来自该版本。ETag 使用强验证标识，不以弱 ETag 支持分片拼接。

允许外部程序修改存储目录时，仅检查大小和修改时间不足以保证一致性；应在下载前重新确认摘要，传输期间采用稳定快照或禁止外部写入的存储约束。普通文件句柄并不保证内容不被原地修改。部署无法提供稳定版本时，必须明确限制，并在检测到变化后中止下载，不宣称支持一致的并发续传。

### 12.4 状态保留与清理（首期）

建议默认：未完成任务空闲 24 小时过期；completed、failed、canceled 状态保留 7 天，允许配置。活动请求和最终校验期间不因普通空闲清理而删除任务。完成状态记录最终路径、大小、SHA-256 和版本，响应丢失后仍可确认结果。

保留状态不等于保留全部临时数据：完成后清理暂存数据；取消后立即清理数据但保留状态；摘要不匹配时清空损坏数据，其它发布失败的暂存数据保留至终态过期，实际磁盘占用仍受可用空间检查约束。清理操作幂等，重启可继续，不能删除正在使用的数据。过期后状态查询明确返回不存在或已过期，客户端不得将其解释为成功。

### 12.5 参数认证（首期）

保留现有可配置 URL 参数认证，同时保留已有 Basic 等认证能力。认证覆盖上传、偏移和状态查询、取消、下载、Hash 响应及 SSE；先认证再接收和处理文件数据。浏览器和 CLI 对每次分片、重试、恢复和事件连接正确携带凭证。

认证参数名不得与 sha256、size 等协议保留参数重名，配置加载时检查并报错。认证参数不接受重复值；不得让 Header、URL 参数等多种认证来源产生身份混淆，沿用并明确统一的认证策略。访问日志、错误输出、启动示例和参考续传命令隐藏真实凭证；跨域只允许配置的来源和必要请求头。

### 12.6 覆盖策略（默认拒绝，支持显式条件覆盖）

默认拒绝覆盖已有文件。显式覆盖使用 ?overwrite=true 并提供目标文件当前强 ETag 的 If-Match 请求头，以条件更新执行；不匹配返回 412。校验、发布与条件检查处于同一受保护流程，避免程序内其他请求替换。旧文件在新文件完整校验成功之前保持可用；禁止先删除旧文件再上传。外部程序不参与程序锁，存储目录应遵守统一写入约束。

### 12.7 配置与资源限制（首期）

配置需明确最大文件大小、默认及最大分片大小、全局和每身份活动上传数、下载并发数、内存缓冲预算、最低剩余空间、任务数据配额、请求空闲超时、校验 Worker 数量、任务有效期及状态保留时间。

分片默认 8 MiB；其他资源默认值依据现有配置和 Windows/WSL 压测确定，并在配置示例中写明单位、范围和零值语义。文件流、校验任务和下载并发均有界，避免以文件大小比例分配内存。最低剩余空间与配额在创建和持续写入时检查，未知长度请求不得绕过限制；已配置身份和会话不能绕过全局限制。

### 12.8 统一结果与增强验收

所有上传入口共用业务错误码、状态字段和内部上传核心；HEAD 通过响应头表达状态，正文响应使用统一结构。浏览器和 CLI 共用状态语义，区分上传完成、校验中、发布成功及失败。

在第 11 节基础上补充：同大小不同内容续传、同账号多客户端竞争、会话接管、分片损坏重试、增量摘要回滚与重启重建、完成响应丢失、保留期和清理竞争、认证参数冲突、下载外部修改与版本变化、并发 Range 恢复、浏览器落盘兼容性和最终 SHA-256 校验。后续覆盖功能还需验收条件冲突和原子替换。每个阶段记录限制和验收结果，不将设计能力描述为已实现能力。
